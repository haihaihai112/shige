# 拾格实施计划

规格见 SPEC.md。项目为独立新建目录，在 develop 分支实现。

## 全局约束

全部 Windows 命令通过 pwsh。只编写独立代码，不读取或复制其他产品源码/资源。真实文件与配置分离；移除格子和改标题不修改内容。所有文件移动可报告失败，禁止覆盖和静默永久删除。无在线运行依赖。

## 任务

1. 工程和接口：验证 .NET SDK 与 WinUI 3 构建，建立独立 Core、App、Tests，固定模块接口。
2. Core：模型、可靠 JSON 配置、路径校验、文件分类、持久化整理预览/执行/撤销/恢复；用真实临时目录 TDD。
3. Platform：Shell 文件操作/回收站/剪贴板、托盘/F7/单实例、启动项、窗口布局恢复与吸附。
4. UI：独立 WinUI 3 原生窗口，格子、选择、文件操作、拖放、设置、手动整理向导；整合 Core 与 Platform。
5. 验证和交付：独立代码审查、修复、构建/测试/启动，中文学习文档、运行脚本、源码和自包含发行包，扫描项目身份。

## 接口与职责

Core 无 WinUI 依赖。App 平台服务通过普通 HWND、回调和路径交互。UI 消费 Core 与 Platform，不允许 Platform 引用窗口类型。Core 使用持久化事务处理整理，普通用户文件操作使用平台服务。

## 验证

- dotnet run --project tests/Shige.Core.Tests；测试框架为无第三方依赖的断言式控制台，可在离线 SDK 上运行。
- dotnet build src/Shige.App -c Release -p:Platform=x64。
- dotnet publish 自包含 win-x64；隔离数据根启动，核对进程路径和可见窗口。
- 最终审查重点：误删/覆盖、配置损坏、事务恢复/撤销、UI 可达性和资源释放。
