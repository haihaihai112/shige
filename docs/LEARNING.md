# 从拾格学习桌面文件工具

## 先理解三种数据

1. **真实文件**属于用户，存放在格子的文件夹中。移除格子从不删除文件夹。
2. **设置**描述怎样显示文件：名称、路径、位置、锁定、图标大小与排序。设置可以导出和恢复，恢复设置不会回滚文件。
3. **整理事务**记录实际文件移动。它与设置分开保存，避免恢复一份旧设置后误以为文件也回到了过去。

## 一次操作经过哪里

用户点击按钮后，窗口先处理界面输入。AppController 协调窗口和设置；Core 处理整理规则和持久化；Platform 与 Windows 交互。Core 不依赖 WinUI，测试可以只创建临时目录，不启动桌面程序。

普通复制、粘贴和回收站删除在 ShellFiles 中；有预览、进度、撤销和恢复要求的桌面整理在 Organizer 中。把两者分开，可避免普通复制任务意外进入整理撤销历史。

## 为什么整理不能只写 File.Move 循环

循环中第三个文件失败时，前两个已经移动。程序必须知道哪些完成、哪些尚未开始，以及重启后应该如何核对。

Organizer 为操作建立持久化记录，并在关键文件系统动作前后保存状态。同卷优先原子改名，保留 NTFS 数据流与元数据；跨卷复制需要校验，不能看到目标文件存在就删除源。无法确定归属的副本或暂存文件会保留，并给出路径，不强制覆盖。

撤销也是一次新事务。先检查原位置是否空闲、目标指纹是否仍一致；否则保留用户的新内容。BatchId 将一次整理中的文件关联起来，使“撤销最近整理”具有明确范围。

阅读时将 Organizer 的状态分支与测试中的中断恢复场景对照，比只读正常执行分支更容易理解。

## WinUI 与线程

WinUI 控件在 UI 线程操作。文件夹监听来自后台线程，必须通过 DispatcherQueue 通知界面；重复事件用短定时器合并，减少闪动。

目录枚举和整理复制在后台完成，界面通过 Progress 接收状态。退出前检查正在进行的整理和普通文件任务，避免应用主动终止自己的文件操作。

App.xaml 虽然很短，仍承担控件资源与 XAML 类型元数据生成。纯 C# 动态创建控件也需要正确的 WinUI 初始化，不能随意删掉该入口。

## 可以怎样精简

| 想保留的版本 | 可以开始研究的位置 |
|---|---|
| 只做文件夹格子 | OrganizeWindow、Organizer、整理设置和对应托盘命令 |
| 只做桌面分类器 | BoxWindow、格子布局及文件夹监听 |
| 学习纯文件算法 | 只构建 Core 与 Core.Tests |
| 学习原生桌面集成 | Platform 中的托盘、F7、单实例、窗口服务 |

每次删除功能先找到入口、运行对象、后台订阅和配置字段，再一起清理。删除按钮后仍保留后台对象，不等于已经精简。先运行测试，修改后再次运行；涉及文件操作时补充实际临时文件场景。

## 测试方法

```powershell
dotnet run --project tests/Shige.Core.Tests -c Release
```

这是无第三方测试依赖的控制台测试运行器：断言失败返回非零退出码。主要测试真实文件结果，不用模拟 File.Move 来证明文件真的移动了。操作系统权限不允许的符号链接测试会明确跳过。

UI 测试要在隔离目录中完成：建立格子、添加测试文件、检查实时刷新，再走预览、确认、移动和撤销。不要把用户真实桌面当作测试夹具。
